# Магические числа и слова: как мы вычистили 1000+ литералов и не сломали игру

*2026-11-27 · рефакторинг, Rust, игровой сервер*

В коде `ld2-rs` давно жили две параллельные вселенные. В одной —
`Event::TYPE`, `Command::TYPE` и аккуратные константы. В другой —
`"evt/combat/hit"` в диспетчере, `"warrior"` в проверке класса,
`(5.0 + dex as f64 * 0.3)` в формуле крита и `text_size(px(12.0))` в
каждом втором окне интерфейса. Пока фича одна — это терпимо. Когда
фич становится сто, каждая строка `"cmd/char.inspect"` превращается в
потенциальную опечатку, а `0.3` — в вопрос «это коэффициент крита или
случайное число?».

Мы решили вынести магические числа и слова в константы. Ниже — как
считали, что вынесли и, главное, что **не стали** выносить.

## Что считаем магическим

**Магическое слово** — строковый литерал, который обозначает доменный
код, а не текст для человека:

- wire-строки `evt/…`, `cmd/…`, `E_…`;
- id из `content/*.json`: предметы, навыки, профессии, локации, мобы;
- перечисления без отдельного типа: слоты (`main_hand`), профили
  (`warrior`), редкости (`rare`), эффекты (`stun`), каналы (`party`).

**Магическое число** — числовой литерал (кроме `0`/`1`) вне
`const`/`static`, у которого есть смысл в предметной области: шансы,
длительности, пороги, множители, лимиты. UI-числа (`px`, отступы,
размеры шрифтов) считаем отдельно — это дизайн-токены.

Сразу договорились, что **не трогаем**: тесты (там литералы — данные
сценария), переводы, канонический `errors.rs` (коды ошибок уже в одном
месте), JSON-ключи wire/статики и строки логов. Иначе «вынос ради
выноса» делает код хуже.

## Аудит: сначала считаем, потом режем

Написали `scripts/magic-audit.py`: он собирает словарь из
`content/*.json`, добавляет доменные перечисления, сканирует
`crates/**/*.rs`, отбрасывает тесты, `const`/`static` и JSON-ключи,
отдельно помечает UI-числа. Запуск:

```bash
python3 scripts/magic-audit.py            # сводка + топ файлов
python3 scripts/magic-audit.py --all      # полная таблица
```

Исходная картина:

- **785** магических слов и **1170** чисел (717 доменных + 453 UI);
- **136** файлов с кандидатами;
- верхняя оценка к выносу — **1850** литералов.

Полная таблица по файлам легла в локальный план
`plans/PLAN-magic-constants.md` (каталог `plans/` в проекте не
коммитится).

## Партии

### 1. Wire-слова

Самое очевидное: `evt/*` и `cmd/*`. В протоколе уже были
`Event::TYPE` и `Command::TYPE`, поэтому не стали плодить вторые
литералы — добавили `ld2-protocol/src/names.rs` с алиасами:

```rust
pub const EVT_COMBAT_HIT: &str =
    <super::evt::CombatHit as Event>::TYPE;
pub const CMD_CHAR_INSPECT: &str =
    <super::cmd::CharInspect as Command>::TYPE;
```

Диспетчеры и роутеры перешли на `names::*`:

```rust
// было
"cmd/char.inspect" => self.char_inspect(env, seq).await,
// стало
names::CMD_CHAR_INSPECT => self.char_inspect(env, seq).await,
```

Итог: **386** замен в 39 файлах. Заодно обновили тест
`command_registry`, который сверяет диспетчер с `ALL_COMMANDS`, — он
теперь понимает `names::CMD_*`.

### 2. Серверный домен

Формулы `stats.rs` перестали быть ребусом:

```rust
let accuracy = (BASE_ACCURACY
    + dex / DEX_ACCURACY_DIV
    + acc_pct.round() as i64)
    .clamp(1, ACCURACY_MAX);
let crit_chance = ((BASE_CRIT_CHANCE
    + dex as f64 * DEX_CRIT_MULT
    + crit_pct).round() as i64)
    .clamp(0, CRIT_CHANCE_MAX);
```

Дальше — бой, мир, сессии: дефолты мобов, интервалы призыва,
эффекты, кулдауны, гейт уровней разделки. Общие значения (профили,
пол, эффекты, типы предметов, слоты, каналы) собрали в
`ld2-server/src/consts.rs`. JSON-ключи сокетов (`rune`, `staff`) не
трогали — это схема, а не значение.

### 3. Клиент: слова и UI-токены

Клиентские слова ушли в `ld2-core/src/domain.rs`: слоты, типы
предметов, редкости, профили, каналы, эффекты, школы, профессии,
направления. Для интерфейса появился `ui_tokens.rs`:

```rust
text_size(px(crate::ui_tokens::FONT_SM))
gap(px(crate::ui_tokens::SPACE_8))
```

Так убрали 151 повторяющееся UI-число. Отдельно вынесли доменные
числа: таймеры смерти, мигание баффов, перезарядку рун, формулу опыта
разделки, секунды в дне.

### 4. Ядро, контент, редактор

В `ld2-core` появились единицы времени, backoff-константы, лимиты
чата и трекера квестов. В `ld2-content` — эффекты `bleed`/`burn`,
типы оружия и минимальный период горения. В `ld2-editor` — свои
`ui_tokens`, направления карты и дефолты нового предмета.

## Что не стали выносить

Это важная часть. Автоматический аудит видел **794** оставшихся
кандидата, но не все из них — «магия»:

- **105 слов** — канонический `errors.rs`. Коды уже в одном месте;
  вторые константы создали бы второй источник истины.
- **JSON-ключи** (`payload`, `rune`, `staff`) — это схема wire, а не
  домен. Замена сломала бы протокол.
- **Конфиг-дефолты и DB-лимиты** (`Default`, `default_*`, `LIMIT`)
  уже именованы контекстом. `const DEFAULT_MP_BASE: i64 = 20` рядом с
  `fn default_mp_max_base() -> i64 { 20 }` — шум, а не польза.
- **Одноразовая UI-геометрия** (ширина конкретного окна, отступ в
  одном месте) — это дизайн-спека, а не константа логики.
- **dev-набор** `session/dev.rs` — тестовые предметы, не игровая
  механика.

## Выводы

1. **Сначала аудит, потом рефакторинг.** Без счёта кажется, что
   «магических чисел немного». Скрипт показал 1850 кандидатов.
2. **Не дублируйте то, что уже типизировано.** `Event::TYPE` лучше
   новой константы с тем же литералом.
3. **JSON-ключи — не магические слова.** Это схема, её нельзя
   заменять на константу в `match`.
4. **UI-числа — токены, а не константы логики.** `FONT_SM` и
   `SPACE_8` живут в одном месте, а не в каждом окне.
5. **Часть литералов лучше оставить.** Если значение — декларативный
   дефолт или одноразовая геометрия, константа только добавит шум.

Код — в `develop` и `main`. Аудит можно перезапустить в любой момент:

```bash

```
