# ADR-010: Бонусы предметов — атрибут, параметр или навык

**Дата:** 2026-11-13 · **Статус:** принято · **Связано:**
`docs/protocol.md` §6 (ItemSnapshot), `docs/skills.md`, `content/items.json`,
`plans/PLAN-M14.md` (F47); ADR-002 (сокеты), ADR-009 (обучение навыкам)

## Контекст

У предметов уже есть три способа усиления: статы (`stats`), улучшение
`+N` и сокеты (руны → урон/заклинания, самоцветы → атрибуты). Но
произвольный бонус — «Сила +3», «Урон +2», «Точность +4%», «+1 к рангу
навыка» — задать нельзя: каждый случай пришлось бы реализовывать
отдельной механикой (как делали для самоцветов в M17/F30c).

Заказчик (M18/F47): **любое оружие, броня или аксессуар** должно нести
бонусы, а целью бонуса может быть **атрибут, параметр или навык**.

## Решение

1. **Единое поле `bonuses`** в контенте (`content/items.json`) и на
   проводе (`ItemSnapshot.bonuses?`, аддитивно §11.2):
   ```json
   "bonuses": [ { "kind": "attr",  "id": "str",      "value": 3 },
                { "kind": "param", "id": "damage",   "value": 2 },
                { "kind": "param", "id": "accuracy", "value": 4, "pct": true },
                { "kind": "skill", "id": "sword",    "value": 2 } ]
   ```
   `kind ∈ attr|param|skill`; `pct` — только у `param`; валидация
   контента (id атрибута/параметра/навыка, `value ≠ 0`, уникальность) —
   `content::tests::items_content_is_valid`.
2. **Хранение:** бонусы определения — в `item_defs.bonuses` (сид
   контента), бонусы инстанса — в `items.bonuses` (миграция `0025`).
   Эффективный список = **контент + инстанс** (слитый в
   `item_snapshot`); инстанс нужен будущим источникам в игре (кузница,
   награды) — сами источники **вне этой фазы** (решение 2026-11-13).
3. **Применение:**
   - `kind=attr` → в `CharacterState.attrs` надетых предметов (там же,
     где считаются самоцветы);
   - `kind=param` → в `stats::derive`: **плоские прибавляются к итогу,
     проценты складываются и применяются к итогу после плоских**
     (решение 2026-11-13 — «сумма % к итогу»); шансы/точность
     ограничиваются своими диапазонами; метка `damage` двигает обе
     границы урона;
   - `kind=skill` → **+N к рангу навыка** в `SkillSnapshot.rank`
     (решение 2026-11-13): участвует в производных характеристиках и
     отображается игроку; порог следующего ранга (`xp_to_next`)
     считается по **заученному** рангу — шкала и `skill.train` остаются
     согласованными.
4. **Показ:** блок «Бонусы» в карточке предмета (`item_view`) —
   «Сила +3», «Точность +4%», «Владение мечом +2».
5. **Источник в игре (этап 2, вне фазы):** dev-сценарий
   `/scenario bonus <uid> <kind> <id> <value> [pct]` пишет бонус
   инстансу и шлёт `evt/item/state` с эффективным списком — задел под
   кузницу/зачарование.

## Последствия

- Клиенты без поля `bonuses` игнорируют его (§11.2) — старые сборки
  просто не показывают блок.
- Сокеты и улучшение остаются отдельными механиками; при добавлении
  источников в игре нужно не дублировать их в `bonuses`.
- Бонусы навыка не влияют на требования экипировки (`requires.skill`
  проверяется по заученному рангу) — иначе предмет самоусиливал бы свой
  же гейт.
