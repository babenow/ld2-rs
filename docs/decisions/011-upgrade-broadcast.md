# ADR-011: Улучшение предмета — строка в лог локации (broadcast)

**Дата:** 2026-11-14 · **Статус:** принято · **Связано:**
`docs/protocol.md` §8 (`evt/upgrade/result`, `evt/upgrade/broadcast`),
§12.2; `plans/PLAN-M14.md` (F49); ADR-010 (бонусы)

## Контекст

Заказчик (M18/F49): при улучшении предмета **в локации всем** видна
строка вида `[имя] улучшил [предмет] до [улучшение]` — для женского
пола «улучшила». Раньше результат улучшения получал **только инициатор**
(`evt/upgrade/result` → личная строка «Улучшение: «X» → +3»), соседи по
локации не видели ничего.

Пол персонажа уже есть (`CharacterState.gender`, M18/F34), тексты лога
уже умеют «Вы …» против имени (M17/F30f, `combat_log`).

## Решение

1. **Новое событие `evt/upgrade/broadcast`** (аддитивно §11.2), а не
   расширение `UpgradeResult` и не повторная отправка `result`:
   - `result` у получателя **закрыл бы его собственную открытую модалку
     улучшения** (обработчик клиента делает `upgrade = None`) и логировал
     бы чужой uid как свой предмет;
   - личное событие остаётся личным: инициатор получает только `result`
     (и свою строку «Вы улучшили …»), broadcast — только остальным.

   Payload: `{ source, source_name, uid, ok, new_upgrade?,
   item_destroyed?, text }`.

2. **`text` готовится сервером** (прецедент `CombatHit.text`): сервер
   знает пол инициатора и адресата строки не существует — для всех
   наблюдателей строка одна:
   - успех: `«{имя} улучшил(а) {предмет} до +{N}»`;
   - провал: `«{имя} провалил(а) улучшение «{предмет}»»`, при
     разрушении — `«… — «{предмет}» РАЗРУШЕН»`.
   Глагол считается по `CharacterState.gender` (`female` → «-ла»).

3. **Рассылка:** как у боя/каста — `world.chars_in_location(location)`
   кроме `char_id` (`world.send_to_char`); поле `location` берётся через
   `current_location` (синхронизация с БД перед захватом мира).

4. **Клиент:** `push_log` текста как есть (`LogKind::Loot`, разрушение —
   `LogKind::Crime`); модалку не трогает. Свою строку инициатора
   формирует сам из `UpgradeResult` («Вы улучшили {предмет} до +N»).

## Последствия

- Старые клиенты игнорируют неизвестный `type` с логом (§11.5) —
  соседи на старой сборке просто не увидят строку.
- Порядок: инициатору ack → `result` → `item/*`; наблюдателям broadcast
  уходит после ответа инициатору — при разрыве соединения наблюдатель
  может пропустить строку (как и события боя).
- Дублирования строк нет: инициатору broadcast не шлётся (проверено
  e2e — у инициатора в очереди первым чужим broadcast был бы его
  собственный).
