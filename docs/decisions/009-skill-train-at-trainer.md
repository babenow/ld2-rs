# ADR-009: Повышение ранга навыка — у тренера в диалоге, при шкале 100 %

**Дата:** 2026-11-13 · **Статус:** принято · **Связано:** `docs/protocol.md` §7, §9;
`docs/skills.md` §2; `plans/PLAN-M14.md` (F44); ADR-008 (диалоги)

## Контекст

Прежняя модель (`cmd/char.xp_invest`, M14/F5): игрок вкладывал очки опыта
(пул квестов) в навык прямо из окна персонажа; шкала росла от вложений и
**автоматически ранковалась**, когда xp набирал порог. Цена тренера бралась
из маркера `locations.json → trainer` и росла с рангом.

Заказчик (M18/F44) сменил модель:

- **повышение навыков из меню персонажа убрать** — окно персонажа больше не
  предлагает вложений;
- **шкала заполняется использованием** навыка (бой/крафт — уже существующий
  `evt/char/xp`), а не вложением пула;
- **повышать ранг можно только при шкале, заполненной на 100 %**;
- обучение происходит **из диалога тренера**, и **плата указана в диалоге**
  (контент), а не в маркере локации;
- платой служат **очки опыта (пул) + плата из диалога**.

Старая команда оставала бы второй дорогой мимо гейта 100 % и вторым
источником цены — поэтому она удаляется, а не отключается на клиенте.

## Решение

1. **Новая команда `cmd/skill.train {entity_id, skill_id}`** (wire `v` не
   меняется — аддитив по §11.2): ack `{rank, xp, xp_to_next, pool_left}` +
   `evt/char/xp` (`amount` отрицательный — списаны очки пула).
2. **`cmd/char.xp_invest` удалена** из контракта и реализации.
3. **Гейты по порядку:** тренер по навыку в локации (маркер M14,
   `E_NO_TRAINER`) → NPC диалога учит этому навыку (`E_NO_TRAINER`) →
   навык существует (`E_XP_POOL`) → **шкала 100 %** (`E_SKILL_NOT_READY`,
   новый код §9) → потолок ранга (`E_RANK_CAP`) → гейт атрибута
   (`E_REQUIREMENT_ATTR`) → очки опыта (`E_XP_POOL`) → плата
   (`E_INGREDIENTS`). Все проверки до списаний.
4. **Цена — из контента диалога:** `content/dialogs.json → npcs[].training:
   [{skill, points, gold, items?}]`; сервер отдаёт этот список в
   `npc.talk` (`training[]`), клиент рисует секцию «Обучение» и шлёт
   команду по кнопке. Маркер локации остаётся **гейтом «тренер здесь»**
   (как у профессий), но его `price` на навыки больше не влияет — рост
   цены с рангом остался только у профессий (`craft.learn`).
5. **Транзакция** (D27): ранг +1, шкала обнуляется, пул − points;
   плата (золото монетами, предметы по `def_id`) списывается отдельными
   шагами после всех проверок.
6. **Окно персонажа:** кнопки вложения (+1/+5/Max) удалены; под шкалой,
   заполненной на 100 %, появляется подсказка «возможно повышение ранга».

## Последствия

- Клиенты без поддержки `skill.train` не могут повышать ранги (старая
  команда удалена) — это ломающее изменение контракта, оформленное
  `[tz-amend]` этим ADR и правкой §7/§9.
- Тесты M12.4/M14 (вложение/гейты/цена) переписаны под `skill.train`:
  шкала выставляется SQL'ем (`common::set_skill`), бой для тестов не гоняется.
- Прогресс навыка по-прежнему копится событиями; пул по-прежнему
  пополняется квестами — меняется только способ его потратить.
