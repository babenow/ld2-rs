# ADR-005: Класс персонажа в списке и клиентский таймер удаления

**Дата:** 2026-11-05 · **Статус:** принято · **Связано:** `docs/protocol.md` §5, §6; `docs/tz.md` ФР-02; `plans/PLAN-M11.md` M11.7 (D19–D21)

## Контекст

Экран выбора персонажей (M11.7): карточки с цветом ника по классу,
подтверждение удаления вводом ника и таймер, отменяемый входом в игру.
Два пробела в контракте/поведении:

1. В `characters[]` (`session.start`/`char.list`) нет класса — а `char.create`
   принимает `profile` (Воин/Вор/Маг). Без поля клиент не может цвет ника
   показывать по классу («клиент не пересчитывает серверные данные»).
2. `char.delete` в §5 немедленный: сервер не знает про таймеры; отложенное
   удаление с отменой «при входе в игру» — чисто клиентская механика.

## Решение

1. **D19 — аддитивное поле `profile` в `CharacterSummary`**
   (`Option<String>`, `warrior`/`rogue`/`mage` — wire-значения `char.create`).
   Сервер без поля валиден: клиент рисует нейтральный цвет. Мок присылает
   (фикстуры + `char.create` прокидывает профиль), контрактные тесты
   ассертят присутствие. Изменение аддитивно: wire `v=1` не меняется,
   egui-клиент поле игнорирует (serde default).
2. **D20 — таймер удаления живёт в клиенте.** Подтверждение (точный ввод
   ника) → `char.delete` **откладывается** на N секунд (`PendingDelete` в
   `ld2-core::store`: `schedule/cancel/tick(now)`). Пока таймер идёт — на
   карточке отсчёт с кнопкой «Отменить». **Экран сменился (вход в игру или
   логаут) → отмена**; тикает только на экране персонажей; отложенных —
   не больше одного (новая запись замещает старую). По истечении клиент
   шлёт обычный `char.delete` — сервер и семантика не меняются.
3. **D21 — длительность выбирается в диалоге**: 5/10/30/60 с (по умолч. 10).

## Последствия

- Таймер сбрасывается при logout/reconnect — удаление не уходит «в фоне»;
  это осознанно: удаление — явное действие с экрана персонажей.
- Клиентская отложенная отправка идемпотентна (одна команда, один ack) —
  §7 ретраи не затрагиваются.
- Добавление `profile` в §6 пример + примечание; будущие серверы шлют поле
  обязательно (мок — эталон).
- Цвета классов — решение UI-слоя (палитра §7.4, светлая тема — затемнение);
  при `profile = null` — нейтральный цвет, без угадывания.
