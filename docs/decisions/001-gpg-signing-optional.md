# ADR-001: Подпись коммитов GPG — рекомендация, а не требование

**Дата:** 2026-11-03 · **Статус:** принято · **Связано:** `CONTRIBUTING.md` §2, §5.4, §6; `PLAN-M0.md` D2

## Контекст

`CONTRIBUTING.md` изначально требовал `git config commit.gpgsign true` и подписанные коммиты как
блокирующее условие PR. На старте проекта у разработчиков (и у CI-агента) нет гарантии наличия
GPG-ключа; строгое правило останавливает первый коммит без benefit для greenfield-проекта.

## Решение

Криптографическая подпись коммитов и тегов — **рекомендация**, не gate:

- `git config commit.gpgsign true` не выставляется автоматически;
- CI-блокирующее условие — только `fmt + clippy + test + build` (green);
- у кого ключ есть — включает подпись локально по желанию;
- возврат к строгому режиму возможен новым ADR (например, перед публичным v1.0).

## Последствия

- Первый коммит и все PR проходят без настройки GPG.
- История `main` не криптографически защищена — принимаем на текущем этапе; митигация — защищённые
  ветки, обязательные PR, CI, включение `main` через GitHub-настройки (branch protection).
