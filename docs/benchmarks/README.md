# Бенчмарки

Локальные балансные отчёты. Сами отчёты — артефакты запуска и в git не
коммитятся; в репозитории лежат только скрипты и эта инструкция.

## Рудные жилы

Считает по реальному контенту (`content/locations.json`) и дефолтному
конфигу (`server.example.toml`): шанс камня, ожидаемое число камней с
жилы, распределение и камни/час.

**macOS / Linux:**

```bash
scripts/bench-ore-gems.sh
# только напечатать, без записи:
scripts/bench-ore-gems.sh --stdout
```

Нужны `bash`, `jq` и `awk` (`brew install jq` / `apt install jq`).

**Windows:**

```bat
scripts\bench-ore-gems.bat
:: только напечатать:
scripts\bench-ore-gems.bat -Stdout
```

BAT вызывает встроенный PowerShell; дополнительных зависимостей нет.
Оба варианта пишут `docs/benchmarks/ore-gems.md` (UTF-8, Markdown).
Файл добавлен в `.gitignore` — это локальный отчёт.

### Допущения

- Уровень профессии равен требуемому уровню жилы: гейт пройден,
  добыча 2 с, шанс успеха 95%.
- Провал добычи (5%) тоже списывает 1 запас жилы, но камня не даёт.
- Одна попытка = одна единица запаса; за успешный бросок падает
  ровно 1 камень.
- Для руды берётся самая ёмкая жила (у олова в лесу есть жила с
  запасом 2).
- «Камней/час» — одна жила: полный запас × 2 с + средний респавн,
  без переходов между жилами.
- Формула камня: `min(1, base × chance_mult × mult + add)`, где
  `base` — `gems.chance`, `chance_mult` — множитель конкретной жилы
  (`gems.chance_mult`, по умолчанию 1.0), `mult` — кирка
  (`mining_master_gem_mult`, ×2), `add` — лампа
  (`mining_lamp_gem_bonus`, +2 п.п.).

### Как читать отчёт

#### Таблица 1. Без инструментов

| Колонка | Что означает |
|---|---|
| Руда, Ур. | название руды и требуемый уровень жилы |
| Запас жилы | сколько единиц можно добыть до респавна (`max`) |
| Шанс/успех | шанс камня в одном **успешном** сборе: `gems.chance × gems.chance_mult` |
| Шанс/попытка | `0.95 × шанс/успех`: провал добычи тоже тратит запас |
| 1 камень в N попыток | `1 / шанс/попытка` — среднее число единиц запаса до камня |
| Камней/жила | `запас × шанс/попытка` — ожидание за полную жилу |
| ≥1 камень/жила | `1 − P(0)` — шанс, что за полный запас выпадет хотя бы один |
| Камней/час | `камней/жила × 3600 / (запас × 2 с + средний респавн)` |

Пример для меди: 3 × 0.59375% = **0.018** камня с жилы; один камень в
среднем раз в **168.4** попытки; `P(0) = 98.2%`; цикл `3 × 2 + 90 = 96 с`
→ **0.67** камня/час.

#### Таблица 2. Эффект инструментов

В каждой ячейке — **шанс камня за успешную добычу / ожидаемое число
камней с полной жилы**. Колонки:

- **Без инструментов** — базовый шанс жилы;
- **Кирка мастера** — `min(1, base × 2)`;
- **Лампа шахтёра** — `min(1, base + 0.02)`;
- **Кирка + лампа** — `min(1, base × 2 + 0.02)`.

Ожидание уже включает 95% успеха и полный запас. Сравнивать стоит по
обоим числам: шанс — «как часто», камней/жила — «сколько за цикл».

#### Таблица 3. Распределение камней с жилы

Вероятности получить ровно `k` камней за полный запас `N`:

`P(k) = C(N,k) × p^k × (1−p)^(N−k)`, где `p` — шанс/попытка из
таблицы 1.

- `P(0)` — жила не дала ни одного камня;
- `P(1)` — ровно один, `P(2)` — ровно два и т.д.;
- сумма всех `P(k)` — 100% (в таблице округление до 0.01 п.п.);
- слева — без инструментов, справа — с киркой и лампой.

### Ограничения

- При уровне ниже требуемого шанс добычи падает, а время растёт —
  камни/час будут ниже.
- Моделируется одна жила; переходы, конкуренция и простои не
  учитываются.
- Средний респавн — `(min_s + max_s) / 2`; фактическое время случайно.
- Двойная руда от лампы на камни не влияет; распределение типов
  камней (`mixed_share`) здесь не считается.
- Точные значения — биномиальное распределение; камень выпадает
  только при успешной добыче.
