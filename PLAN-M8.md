## Ключевая проблема и архитектура мока

Сейчас мок — **одна `Session` на все соединения** (`Arc<Mutex<Session>>` в `server.rs`) без broadcast:
второй клиент перезаписал бы `authenticated`/`char`, а события (чат, пати, сделка) уходят только вызвавшему
соединению. DoD с двумя клиентами невозможен без перестройки:

- **`World`** (новый, `Arc<Mutex<World>>`, один на сервер): общий монотонный `state_version`,
  реестр соединений `conns: conn_id → sender` (рассылка в сокеты), реестр игроков
  `players: char_id/имя → conn_id`, межигровое состояние `party`/`trade`/`guild`,
  приглашения, сохранённые состояния аккаунтов (`char`+`location` для resume после обрыва).
- **`Session`** — per-connection (своя на каждое WS-соединение): `authenticated`, аккаунт, свой
  `char`/`location`/`previews`/`crime_log` и пр.; хранит `Arc<Mutex<World>>`.
- **Дисциплина локов:** всегда `session → world`, никогда обратно (`World` не лочит `Session`) —
  иначе deadlock. Рассылка другим = `World` пишет в их `sender` (tokio mpsc, без лока сессии).
- **DoD-сценарии в World:** whisper роутится по имени адресата; пати-приглашение —
  `evt/party/updated {party: null, invite: {...}}` второму клиенту (новое опциональное поле `invite`,
  совместимо без bump — §11), `party.accept {invite_id}` собирает группу и шлёт обеим сторонам;
  сделка — одна на World, каждая сторона получает зеркальный `you/them`, `version` общий,
  при `done` — обмен применяется через outbox-сигнал в сессии (предметы: `evt/item/added|removed`).
- **Второй аккаунт** в фикстурах: `demo2/demo123` → персонаж `c2` (свой `session_config`/список слотов
  по аккаунту); `auth.login` принимает оба, `auth.resume` восстанавливает `char`+`location` из World.
- Контракт `ld2-protocol` и golden **не меняются** (новые опциональные поля — §11).

## Правила

Контракт `ld2-protocol`/golden не трогать (§11: новые опциональные поля — без bump); лимиты чата —
из `session.start` (channels/max_len/cooldown_s); клиент не пересчитывает серверное (version — истина
сервера); коммиты RU + `Milestone: M8`; PR через `--body-file`.

## Риски

- Перестройка `Session`/`World` — самая рисковая часть M8: все существующие тесты (контракт 20,
  world_flow 6, account/full_stack/transport) должны пройти без изменений семантики (state_version
  1001/1002 после login+select — сохранить); сначала M8.1 + прогон всего workspace.
- Deadlock-дисциплина локов (только session → world); рассылка — через senders, не через лок сессии.
- Сброс истории чата при смене персонажа (ФР-13) — не забыть в reset-ветке (рядом с `quest_tracker`).
- 7 вкладок в листе (добавляется «Гильдия») — тесно; при росте (M9) пересмотреть в отдельной задаче.
- `/scenario` — dev-команда мока: объявить известной в слэш-парсере (passthrough), иначе сломаются
  чат-триггеры сценариев.
- Сделка и пати в моке — одна World-сущность на сервер (для DoD двух клиентов достаточно).
